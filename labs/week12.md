# 12주차: 공개 팀 프로젝트

목표: Issue로 일을 나누고 개인별 코드 PR과 교차 리뷰를 남깁니다.

교수자가 이 저장소의 **Use this template → Create a new repository**로 팀별 **Public** 저장소를 준비합니다. 기본 branch만 포함하고 팀원에게 쓰기 권한을 부여합니다. 별도의 수업 Organization이 준비되지 않았으면 교수자 계정 아래 팀 저장소로 시작할 수 있습니다. 템플릿 복사본은 독립 프로젝트이며 이후 PR은 **자기 팀의 main**으로 보냅니다.

1. 팀 저장소를 clone하고 README의 가상환경·설치·실행·테스트 절차를 확인합니다.
2. 팀 README와 workflow badge의 저장소 경로를 자기 팀 것으로 바꾸고 프로젝트 목적을 적습니다.
3. 종류/가격 검색에 추가할 기능을 Issue로 나눕니다. 입력·출력·정상/경계 조건과 담당자를 적습니다.
4. 각자 main에서 새 branch를 만들어 구현합니다. 한 PR에 한 기능을 담습니다.
5. 작성자·리뷰어·실행 확인자 역할을 순환합니다. 다른 팀원이 실제 실행한 뒤 병합합니다.

[기여 과제](../docs/tasks.md)의 이름 검색·정렬·CSV 저장은 팀 기능 후보로 재사용할 수 있습니다. T01 CSV만 추가한 학생도 이 단계에서는 Python 코드 변경을 맡습니다.

시작 코드의 Actions는 PR에서 테스트를 실행합니다. 먼저 실패한 단계와 오류 메시지를 읽습니다. YAML 전체 작성은 필수 과제가 아닙니다. 팀 원본에 학생이 자신의 fork에서 PR을 보낼 때와 팀 원본의 작업 branch에서 PR을 보낼 때의 차이도 설명합니다.

제출: 개인별 담당 Issue·코드 PR·타인 리뷰 URL, 팀 실행 결과. 성적·학번을 공개 문서에 넣지 않습니다. 제출 마감은 LMS 공지를 따릅니다.
