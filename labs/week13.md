# 13주차: 개인 오류 재현과 테스트 보강

목표: 자신의 12주차 코드를 검사하고 경계 조건 테스트를 추가합니다. 이론·시연 20분, 개인 실습 170분, 정리 10분입니다. 다른 학생의 프로그램을 검토하는 과제는 없습니다.

1. **입력 실험 30분:** 내 저장소를 최신화하고 정상 입력·빈 CSV·결과 없음·잘못된 가격·정수가 아닌 옵션·없는 경로를 실행합니다. 예상과 실제를 비교하고 commit SHA를 기록합니다.
2. **Issue·재현 정리 25분:** 실제 오류가 있으면 최소 입력, 명령, 기대/실제 결과를 내 Issue에 적습니다. 정상 처리된 입력을 버그라고 쓰지 않습니다. 오류가 없으면 아직 검증하지 않은 경계 조건을 선택합니다.
3. **테스트·수정 65분:** `fix/input-validation` 또는 `test/edge-cases` branch를 만듭니다. `tests/test_week13.py`에 기존 테스트와 다른 경계 조건 테스트를 **2개 이상** 추가합니다. 오류가 있는 경우 수정 전 실패·수정 후 성공을 남깁니다. 오류가 없으면 테스트 보강만 해도 됩니다.
4. **자동검사·교수자 피드백 반영 30분:** 아래 검사를 실행하고 PR을 작성합니다. 실패 항목 또는 교수자 의견에 따라 같은 branch에서 수정합니다.
5. **설정·문서 점검 20분:** `.gitignore`, LICENSE, 의존성, 가짜 설정 예제의 공개 범위를 확인하고 `reports/week13.md`를 작성합니다.

```bash
python -m unittest discover -s tests -v
python -m campus_tool --data-dir examples/submissions
python tools/autograde.py --week 13 --output output/week13-checks.json
git diff --check
```

자동검사는 12주차 기능 유지, 전체 테스트, 주차별 테스트 2개 이상, 입력 오류의 종료 코드 2와 stderr, 빈 목록의 정상 처리를 확인합니다. **테스트의 의미와 재현 설명의 타당성은 교수자가 확인합니다.** 이미 정상 동작하는 코드를 일부러 망가뜨려 제출하지 않습니다.

권장 테스트 후보: CLI의 정수가 아닌 `--max-price`, UTF-8이 아닌 CSV, 공백뿐인 필드, 서로 다른 파일의 중복 ID, keyword와 다른 조건의 경계 조합. 기존 `tests/`를 읽고 새로운 검증 대상을 고릅니다. 모든 기존 테스트와 기본 데이터는 유지합니다.

PR 대상은 본인 저장소 main입니다. `reports/week12.md`도 보관합니다. 수정 PR 또는 테스트 보강 PR, 제출 SHA, 자동검사 실행 결과, 최소 재현과 변경 이유를 LMS에 제출합니다. 타인 리뷰 URL은 받지 않습니다. 성적과 교수자 평가 메모는 공개하지 않습니다.
