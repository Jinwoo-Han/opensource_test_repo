# 13주차: 테스트와 품질 개선

목표: 다른 팀이 보고한 문제를 재현하고 수정 전 실패·수정 후 성공을 보여 줍니다.

1. 짝 팀의 공개 저장소를 새 폴더에 clone하고 README만 보고 실행합니다.
2. 정상 입력뿐 아니라 빈 목록, 검색 결과 없음, 한글, 잘못된 금액·CSV 등을 확인합니다. 이미 정상 처리되는 입력을 버그로 제보하지 않습니다.
3. 문제가 있다면 최소 입력, 명령, 실제/기대 결과, commit SHA를 Issue로 전달합니다. 문제가 없다면 재현 확인 기록과 개선 제안을 남깁니다.
4. 자기 팀은 담당 Issue를 골라 실패하는 테스트를 작성하고, 코드를 고쳐 같은 테스트를 통과시킵니다.
5. PR에 수정 전후 결과를 적고 다른 학생의 리뷰를 받습니다.

```bash
python -m unittest discover -s tests -v
python -m campus_tool --data-dir examples/submissions
git diff --check
```

표준 라이브러리 `unittest` 예시는 `tests/`에 있습니다. 정상 기능을 일부러 망가뜨린 코드를 공통 main에 병합하지 않습니다. 팀 프로젝트에 버그가 없다면 교수자가 제시한 새 경계 조건이나 아직 없는 테스트를 추가합니다.

보안 활동에서는 가짜 설정값으로 `.gitignore`와 `.env.example`을 검토합니다. 실제 토큰·비밀번호를 업로드하지 않습니다. 사용자 문자열을 `eval`로 실행하는 예제의 위험을 설명하고, 문자열/숫자 값 처리로 바꾸는 작은 과제를 진행할 수 있습니다. 이 과제를 위해 위험한 실행 경로를 배포 코드에 추가하지 않습니다.

의존성 목록과 LICENSE, 제출 파일의 범위도 확인합니다. CI 성공만으로 모든 보안 문제가 없다고 판단하지 않습니다.

제출: 재현 가능한 Issue, 수정 PR 또는 테스트 보강 PR, 실제 테스트 결과, 동료 리뷰와 자신이 설명할 수 있는 변경 이유.
