# 교수자 운영 안내

모든 학생이 개인별로 수행합니다. 팀 프로젝트·짝 리뷰·타인 리뷰 제출은 운영하지 않습니다. 검토는 교수자 리뷰 또는 Autograder 중심으로 진행하며 주차 시작 시 사용할 방식을 LMS에 공지합니다.

## 저장소와 권한

- 9~10주차는 학생이 직접 만든 공개 개인 저장소입니다.
- 11주차에는 공통 저장소를 Fork하고 원본으로 기여 PR을 보냅니다. 원본 쓰기 권한을 학생에게 일괄 부여하지 않습니다.
- 공통 main은 교수자가 검사와 변경을 확인한 뒤 merge commit으로 병합합니다. 기존 보호 규칙의 PR 경유·`tests` 검사 요구를 유지합니다. 별도 승인자 1명을 강제하지 않으므로 소유자 혼자 운영할 수 있습니다.
- 12~14주차는 학생 계정의 공개 `oss-individual-labs`입니다. 각 학생이 템플릿 기본 branch에서 생성하고 개인 main으로 PR을 만듭니다. 팀 저장소나 팀원 권한 배포는 필요하지 않습니다.
- 개인 저장소의 필수 동료 승인 규칙은 설정하지 않습니다. 교수자 collaborator 초대 없이도 공개 변경을 읽고 피드백할 수 있습니다. 검사·피드백 반영 후 병합은 학생이 수행합니다.

## 수업 전 준비

1. README의 Ubuntu·Python 3.10+·venv·GitHub 인증 절차를 확인합니다.
2. 시작 코드의 기본 실행·테스트·CI를 확인합니다. 12주차 배포 직전 원본 main의 기준 SHA를 LMS에 기록하고 실습 중 시작 버전을 고정합니다.
3. 11주차 T01 반복 Issue는 열어 둡니다. 각 학생은 별칭별 파일을 추가합니다. T02~T07을 원본에 기여할 경우에는 한 학생씩 맡깁니다.
4. 12주차 기본 과제는 모든 학생이 각자 `--keyword`를 구현합니다. 공통 원본에 같은 기능의 PR을 여러 번 제출하지 않습니다. 선택 기능은 기본 완료 후 진행합니다.
5. [Autograder 안내](autograding.md)에 따라 제출 SHA 검사 워크플로를 baseline으로 한 번 실행합니다. baseline 통과는 주차 과제 완료가 아닙니다.

## 검토량 관리

교수자 리뷰 중심이면 매주 학생별 핵심 PR 한 건을 보고 피드백합니다. 자동검사 중심이면 공개 기준으로 일괄 확인하고 실패·예외를 먼저 검토합니다. 정상 통과본도 설명과 테스트의 타당성을 표본 또는 수업 중 개별 질문으로 확인합니다. 학생끼리 사전 리뷰하게 하는 단계는 없습니다.

현재 제공되는 수동 Autograder는 **한 실행에 학생 한 명의 SHA**를 검사합니다. 전체 학생 자동 수집·일괄 실행·LMS 점수 전송은 구현하지 않았습니다. 명단과 저장소 URL의 연결은 LMS에서 관리합니다. 학생 계정 생성·권한 변경도 하지 않습니다.

fork PR의 실행 승인 대기, 네트워크 오류, 교수자 병합 대기는 학생 기능 실패와 구분합니다. 승인 전 diff와 workflow 변경을 확인하며, 학생 코드를 교수자 PC나 관리 비밀정보가 있는 환경에서 자동 실행하지 않습니다.

## 제출·평가

- LMS 제출: 개인 PR URL, 전체 제출 SHA, 검사 실행 URL 또는 JSON, 실제 명령·출력, 변경 이유. 14주차는 Release URL과 내려받은 파일의 해시·설치 결과도 받습니다.
- 공개 Actions 결과는 통과/실패 피드백입니다. 성적·학번·비공개 코멘트는 LMS에 둡니다. 기존 출석·과제·시험 비율을 바꾸지 않습니다.
- 학생 저장소의 녹색 CI만으로 평가하지 않습니다. 원본 검사기 버전을 고정해 제출 SHA를 검사하고, 보고서 의미·회귀 테스트의 적절성·Release 첨부물은 교수자가 확인합니다.
- 학생이 과제용 보고서에 그 보고서 자신의 commit SHA를 적도록 요구하지 않습니다. SHA는 최종 제출 시 LMS에서 고정합니다.
- 13주차에는 실제 버그가 없어도 의미 있는 경계 조건 테스트 보강을 인정합니다. 14주차는 다른 학생 확인 대신 새 환경 설치·Autograder·교수자 확인으로 대체합니다.
