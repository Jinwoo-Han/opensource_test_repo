# 개인 실습 Autograder

이 저장소는 **공개 기능 검사와 형성평가 피드백**을 제공합니다. 숫자 점수·성적표를 생성하거나 LMS에 자동 전송하지 않습니다. 성적은 기존 평가 기준에 따라 교수자가 LMS에서 확정합니다.

## 두 가지 운영 방식

| 방식 | 학생 | 교수자 |
|---|---|---|
| 교수자 리뷰 중심 | 개인 PR·실제 실행 기록 제출, 의견 반영 | 목적·변경·테스트·설명을 읽고 피드백. 기존 Actions는 보조 자료 |
| Autograder 중심 | 공개 기준에 맞춰 구현, 실패 항목 수정, 제출 SHA·실행 결과 제출 | 학생별 전체 SHA로 공통 검사 실행. 실패·예외를 우선 확인하고 설명·테스트 의미·릴리스 파일을 표본 또는 별도 확인 |

어느 방식도 짝 리뷰를 요구하지 않습니다. `tests` CI가 녹색인 것과 해당 주차 과제를 완료한 것은 다릅니다. 기존 CI는 기본 회귀 테스트·빌드를, 주차별 Autograder는 아래 과제 기준을 확인합니다.

## 검사 범위

| 선택 | 자동으로 확인하는 내용 | 별도로 확인할 내용 |
|---|---|---|
| baseline | 필수 파일, 테스트가 실제 발견·통과되는지, 기본 데이터 출력 | 환경 확인용이며 과제 완료 판정 아님 |
| 12 | baseline + keyword 6개 동작 기준 + week12 기록 파일 | 구현 이유, README의 설명 정확성 |
| 13 | 12 + 주차 테스트 2개 이상 + 입력 오류/빈 목록 처리 + week13 기록 | 회귀 테스트의 의미, 변경 전후 설명 |
| 14 | 13 + wheel·sdist 빌드, 소스 폴더 밖 새 환경 설치, 추가 기능·데이터·버전 + week14 기록 | 실제 Release 첨부물의 일치, 개인 설명 |

주차 검사는 누적됩니다. 공통 요구 기능은 `--keyword`, 모듈명은 `campus_tool`, 배포 이름은 `oss-campus-tool`입니다. 기본 예시 데이터·기존 출력·테스트를 유지합니다. 기록 파일은 존재 여부만 검사하므로 그 내용의 정확성까지 자동 판정하지 않습니다. 비어 있지 않은 보고서나 단순히 통과하는 테스트만으로 이해도를 증명할 수는 없습니다.

## 학생의 로컬 확인

가상환경에서 README의 설치를 마친 뒤 실행합니다. 14주차에는 `python -m pip install build`도 필요합니다.

```bash
python tools/autograde.py --week 12 --output output/week12-checks.json
# 다음 주에는 --week 13 또는 --week 14
```

항목별 PASS/FAIL과 JSON 결과가 나옵니다. 하나라도 실패하면 종료 코드 1입니다. 시작 코드에는 keyword 정답을 넣지 않았으므로 12~14 검사가 처음에 실패하는 것이 정상입니다. 학생은 검사를 삭제하거나 완화하지 말고 구현과 기록을 보완합니다.

## 교수자의 제출 SHA 검사

학생 저장소의 테스트나 workflow가 바뀌어도 그 녹색 표시만으로 판정하지 않습니다. **교수자 원본 저장소의** Actions → **Grade individual submission** → **Run workflow**에서 Branch는 main으로 두고 입력합니다.

1. `repository`: 공개 개인 저장소의 `계정/저장소`.
2. `commit`: LMS에 제출된 **40자리 전체 SHA**. 변경될 수 있는 branch 이름을 넣지 않습니다.
3. `week`: 12, 13 또는 14. baseline은 수업 전 실행 점검용입니다.

이 워크플로는 실행한 교수자 버전의 검사기를 따로 가져오고, 지정한 학생 SHA를 별도 경로에 checkout합니다. 기본 코드는 PYTHONPATH로 제출본 src를 읽습니다. 14주차에는 제출본에서 직접 빌드한 wheel을 새 환경에서 검사합니다. 결과는 해당 실행의 Summary 및 **Show feedback** 로그에서 확인합니다. 실행 URL과 학생 SHA를 LMS에 함께 기록합니다.

수동 실행에는 원본 저장소 쓰기 권한이 필요하고 workflow 파일이 기본 branch에 있어야 합니다. [공식 실행 안내](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow)

같은 기준을 유지하려면 채점 기간에 원본 검사기를 변경하지 않고, 결과와 함께 워크플로 실행의 교수자 commit도 보관합니다. 설치·네트워크·checkout 오류는 학생 기능 실패와 구분해 재실행합니다.

## 운영 경계

- 공개 저장소이므로 검사 기준·실행 로그·통과 여부는 공개될 수 있습니다. 명단·학번·점수·비공개 피드백은 입력이나 결과에 넣지 않습니다.
- 권한은 `contents: read`, checkout 자격증명은 저장하지 않으며 비밀정보를 전달하지 않습니다. GitHub-hosted 임시 runner를 사용하고 self-hosted 교수자 PC에서는 학생 코드를 자동 실행하지 않습니다.
- 공개 검사기는 숨은 시험 채점 환경이나 부정행위 방지 장치가 아닙니다. 학생 코드가 실행되는 환경이므로 악의적인 코드까지 견디는 격리 채점 시스템으로 간주하지 않습니다. 숨은 테스트·자동 점수 확정이 필요해지면 별도 채점 환경을 설계합니다.
- 10주차 `oss-week09`의 인사말 실습에는 이 Python 패키지 검사기를 적용하지 않습니다. 교수자가 PR·충돌 기록을 확인합니다. 11주차 공통 기여는 기존 `tests` CI와 교수자 검토를 사용합니다.
- fork PR의 Actions 실행 승인 대기는 테스트 실패와 다릅니다. 교수자는 diff·workflow 변경을 확인한 뒤 승인합니다. [공식 안내](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/approve-runs-from-forks)
